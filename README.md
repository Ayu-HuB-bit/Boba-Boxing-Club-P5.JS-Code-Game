Boba Boxing Club - Interactive p5.js UX Engineering & Logic Sandbox

## 📋 Project Overview
Boba Boxing Club is a real-time, canvas-based interactive web application engineered using the p5.js library. Rather than serving as a standalone game concept, this repository functions as a dedicated front-end UX engineering sandbox. 

The primary objective of this project was to implement, stress-test, and validate human-computer interaction (HCI) feedback loops, strict visual accessibility parameters, and ethical design structures within a high-velocity script environment.

---

## 🔬 UX Engineering & Functional Logic Frameworks Applied
The mechanical architecture and interface rendering for this application were built and audited utilizing rigorous software compliance and behavioral design rules:

### 1. High-Responsiveness Signs & System Feedback Loops
To ensure the interface feels completely reliable during intense interactive states, the input-to-canvas rendering path was built under standard usability heuristics:
* **Immediate System Status Visibility:** Programmed instant non-diegetic visual signs (e.g., dynamic resource bars, action cooldown states, and variable metric counters) that update in real time based on active system states.
* **Input-Action Confirmation Telemetry:** Engineered explicit visual confirmation frames upon user key-triggers. If a user inputs an action, the canvas provides immediate, distinct feedback, preventing input confusion or double-triggering during rapid interactions.
* **State Machine Error Prevention:** Structured the underlying state loops to handle rapid input saturation, isolating and preventing invalid control transitions (e.g., action spamming bypassing cooldown states).

### 2. Digital Ethics & Deceptive Pattern Mitigation
Following strict user advocacy principles documented across ethical UX literature, the interactive loops were engineered to completely eliminate manipulative mechanics:
* **Anti-Dark Pattern Architecture:** Design layers are intentionally free of artificial loss aversion, forced engagement traps, or hidden data gates, establishing a pure model of transparent user autonomy and clear exit paths.
* **Cognitive Load Fairness:** The interface avoids visual clutter or flashing elements that trigger sensory exhaustion, ensuring the user's focus is spent entirely on executing intentional interaction goals.

### 3. Inclusive Design & WCAG Accessibility Calibration
To prove that interactive front-end environments can be built inclusively, the visual layout assets were audited against web accessibility guidelines:
* **Color Deficient Optimization:** Color mapping choices were strictly evaluated using contrast checking models to ensure readability across diverse user visual profiles, specifically accommodating **Protanopia** and **Deuteranopia** color-vision variations.
* **Focal Hierarchy Alignment:** Designed clear spatial orientation pathways on the canvas, ensuring essential interface text, metric displays, and active entities maintain strong visual separation and structural hierarchy.

## 🛠️ Logic Verification & Quality Assurance Sandbox Tasks
To guarantee functional stability, the script compilation was run through manual QA testing cycles:
* **Boundary Parameter Analysis:** Tested interaction collision zones at maximum and minimum spatial borders to ensure coordinate math prevents asset Clipping or boundary dropouts.
* **Input Stress Testing:** Simulated extreme button saturation to verify state-machine calculation stability and prevent frame-rate execution crashes.
